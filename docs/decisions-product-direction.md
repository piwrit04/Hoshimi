# 决策记录：产品方向（Grill）

- **日期**：2026-10-25
- **强度**：拷打

## 已确定

- **D-G1 第一用户**：仅自己（店长），非对外客户/工作室
- **D-G2 核心痛点（口述）**：记单靠微信备注 + 手写，临时昵称后期对不上；回头客靠记忆，客户改名/头像易丢识别
- **D-G3 为何还没日用**：老订单需导入并规范化；单量少时不急；单量上来后 UI/各处显得乱
- **D-G4 游戏范围（当前 + 规划）**：伊莫、异环、鸣潮；后续无限大、白银之城等（多游戏仍是目标，但是否第一版全做待定）
- **D-G5 客户识别**：手机号 + 内部备注名为主；不依赖微信号/微信昵称（可改）
- **D-G6 老单来源**：Excel、微信聊天、闲鱼记录；Cheezit 另一版 UI，基本不管/不迁
- **D-G7 规范化含义**：统一「下单内容」口径（聊天说法、Excel 不同命名、同内容异名要对齐）
- **D-G8 第一版游戏范围**：只跑通异环；其他游戏流程类似，后置
- **D-G9 异环订单字段（用户口述）**：客户、联系方式、下单渠道、游戏、具体内容、服务器、打手、金额、实际到手、是否打完、下单时间、完成时间；备注可选
- **D-G10 导入策略**：C — 先 Excel 批量；微信/闲鱼仅核对补漏
- **D-G11 两周成功标准（初版）**：用户曾要 A+C（Excel 老单全进且口径统一 + UI 再打磨）；已被 D-G13 修正
- **D-G12 录单**：客户↔联系方式联动匹配/无则新建；游戏顺手；内容+金额必填；时间自动；其余可顺手填。核心未决是「列表/详情显示优先级」
- **D-G13 两周主目标改为 C**：先打磨 UI 好看且实用；导入 A 后置。用户理由：多次因 UI 重构；功能基本 OK，缺完整测 BUG
- **D-G14 UI 验收**：对齐大厂信息层级 + 打磨自有组件库（可复用到其他个人项目）；用户自认非设计师，需参考外部
- **D-G15 先改订单列表（A）**
- **D-G16 痛点实例**：订单管理 ≈ 最新单 vs 待办 ≈ 未完成单，内容高度重叠；缺「快捷处理 / 一眼未完成」的形态决策
- **D-G17 信息架构**：页面分布完整重开讨论（订单/待办等），不锁死 Q18 选项
- **D-G18 两周节奏修订**：先补齐组件库未完工组件 + 全组件测 BUG，再正式改业务页（推翻「80% 订单列表」建议，以用户决定为准）
- **D-G19 参考产品**：用户无指定，由助手推荐后用户挑选
- **D-G20 组件库停手线**：A — /components 全部有预览且点过无阻塞 BUG 后再改业务页
- **D-G21 首页意向**：要「工作台」，每天最想看到的信息（具体模块待定）
